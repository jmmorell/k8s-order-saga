# Day 2 — kind + Helm: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make local-up` creates a three-node kind cluster running the whole saga (five services, NATS, Postgres, Mailpit) with `orders` reachable from the host through the Gateway API, and `make local-smoke` proves it.

**Architecture:** One generic Helm chart (`charts/service`) deploys every Go service from a small values file. Platform components live in a `platform` namespace: NATS from its official chart, Postgres and Mailpit as plain manifests. Envoy Gateway implements the Gateway API; its proxy is exposed as a fixed NodePort that kind maps to `localhost:8080`. Idempotent shell scripts behind Makefile targets do the bootstrap; day 4 replaces them with Argo CD using the same chart and values.

**Tech Stack:** kind 0.33, kubectl 1.33, Helm 4, kubeconform, Envoy Gateway (Gateway API v1), NATS Helm chart, Postgres 17, Mailpit v1.33.1, Docker (OrbStack).

**Spec:** `docs/superpowers/specs/2026-11-12-k8s-portfolio-design.md` (§6 "Platform / Local", §7 day 2)

## Global Constraints

- Everything in the repo is in **English**.
- Cluster name `order-saga`; kubectl context `kind-order-saga`. **Every `kubectl`/`helm` call in scripts and Makefile passes `--context kind-order-saga` / `--kube-context kind-order-saga`** — never rely on the current context (the machine also has an OrbStack context).
- kind: 1 control-plane + 2 workers, default CNI (kindnet).
- Namespaces: `shop` (the five Go services, Gateway, HTTPRoute), `platform` (NATS, Postgres, Mailpit), `envoy-gateway-system` (Envoy Gateway).
- Only `orders` is reachable from the host: `http://localhost:8080` → kind port mapping → NodePort `30080` → Envoy proxy → `orders:8080`. The HTTPRoute exposes only the `/orders` path prefix. Nothing else gets a NodePort, LoadBalancer or host port.
- Do not use ingress-nginx.
- In-cluster addresses: `nats://nats.platform.svc.cluster.local:4222`, `postgres.platform.svc.cluster.local:5432`, `mailpit.platform.svc.cluster.local:1025` (SMTP) / `:8025` (API/UI), `http://orders.shop.svc.cluster.local:8080`.
- Images: `k8s-order-saga/<service>:dev`, built with the existing `Dockerfile`, loaded with `kind load docker-image`; `imagePullPolicy: IfNotPresent`.
- **No secrets in Git.** The Postgres password is generated by the bootstrap script (`openssl rand -hex 16`) into a Secret named `postgres` (key `password`) in both `platform` and `shop`, created only if absent.
- Every container has resource **requests and limits**. The whole cluster must fit in 6 GB.
- Every Go service container: `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`, `seccompProfile: RuntimeDefault`. (NetworkPolicies, Pod Security Admission labels and RBAC tightening are day 4 — do not add them.)
- Probes on every Go service: liveness `GET /healthz`, readiness `GET /readyz`, port `8080`.
- Third-party chart and image versions are **pinned explicitly** (no `latest`, no floating chart version). Pick the latest stable at implementation time and record it in the ADR.
- All scripts are idempotent: running `make local-up` twice succeeds and changes nothing the second time.
- Compose keeps working: `make up` / `make smoke` are untouched in behaviour. Compose and kind both use host port 8080 — never run both at once; scripts fail with a clear message if 8080 is taken.
- A short ADR in `docs/adr/` precedes each platform piece. Between equivalent options, pick the easiest to explain.
- `make lint` stays at 0 issues; `go test -race ./...` stays green.

## Review Focus

1. **A service pod starts before NATS or Postgres is ready** → it must become Ready on its own (restart or wait), with no manual step. Checked in Task 4 (`local-up` on a fresh cluster with no ordering waits between services).
2. **A pod is deleted while traffic flows** → the Deployment replaces it and orders keep completing; nothing lands in the DLQ. Checked in Task 4.
3. **`make local-up` is run twice, or after a partial failure** → second run succeeds; no duplicated resources, no regenerated password (which would lock services out of Postgres). Checked in Tasks 3 and 4.
4. **A handler panics** → the service must not crash-loop; the message follows the retry/DLQ path. Test in Task 1.
5. **The wrong kube context is active** (OrbStack's) → scripts still act only on `kind-order-saga`. Checked in Task 3 by switching context before running.

### Task 2: Generic Helm chart for the Go services

**Files:**
- Create: `docs/adr/0006-generic-helm-chart.md`
- Create: `charts/service/{Chart.yaml,values.yaml}`, `charts/service/templates/{_helpers.tpl,deployment.yaml,service.yaml,serviceaccount.yaml}`
- Create: `deploy/local/values/{orders,inventory,payments,notifications,loadgen}.yaml`
- Create: `scripts/chart-test.sh`
- Modify: `Makefile` (target `chart-test`)

**Interfaces:**
- Produces — chart `service` (version `0.1.0`), release name = service name. Values contract:

```yaml
image: { repository: "", tag: dev, pullPolicy: IfNotPresent }   # repository required
replicaCount: 1
port: 8080
service: { enabled: true }          # ClusterIP on .port; loadgen and workers still get one (probes/metrics later)
env: {}                             # map name → string value
secretEnv: []                       # list of { name, secretName, key } — rendered BEFORE env so env can use $(NAME)
resources: { requests: { cpu: 25m, memory: 32Mi }, limits: { cpu: 250m, memory: 128Mi } }
terminationGracePeriodSeconds: 30
```

- Rendered objects: `ServiceAccount` (name = release), `Deployment` (labels `app.kubernetes.io/name: <release>`, `app.kubernetes.io/part-of: order-saga`), `Service` (if enabled). The container always sets `HTTP_ADDR=:<port>`, the security context and probes from Global Constraints. The template fails with a clear message if `image.repository` is empty (`required`).
- Per-service values (exact env):
  - `orders`: `replicaCount: 2`; `secretEnv: [{name: POSTGRES_PASSWORD, secretName: postgres, key: password}]`; `DATABASE_URL: postgres://postgres:$(POSTGRES_PASSWORD)@postgres.platform.svc.cluster.local:5432/orders?sslmode=disable`; `NATS_URL` from Global Constraints.
  - `inventory`: same pattern, database `inventory`; `RESTOCK_INTERVAL: 1m`.
  - `payments`: same pattern, database `payments`; `PAYMENT_FAILURE_RATE: "0.1"`; `PAYMENT_LATENCY_MS: "200"`.
  - `notifications`: `NATS_URL`; `SMTP_ADDR: mailpit.platform.svc.cluster.local:1025`.
  - `loadgen`: `TARGET_URL: http://orders.shop.svc.cluster.local:8080`; `RATE_PER_SEC: "2"`; `OUT_OF_STOCK_RATIO: "0.05"`.
- `make chart-test` runs `scripts/chart-test.sh`, which for each of the five values files runs `helm lint --strict` and `helm template | kubeconform -strict -summary`, then asserts with `grep`/`yq`-free shell checks that: every rendered Deployment has `readOnlyRootFilesystem: true`, `runAsNonRoot: true`, both probes, requests and limits; `orders` renders `replicas: 2`; in `orders` the `POSTGRES_PASSWORD` env entry appears before `DATABASE_URL`; rendering without `image.repository` fails. Prints `CHART OK`.
