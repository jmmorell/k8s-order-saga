# Day 3 — Observability: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the kind cluster, one order can be followed as a single trace across the four saga services. A Grafana dashboard shows the saga, an SLO is defined, and alerts for payment errors, the DLQ and orders stuck in PENDING reach Mailpit by email. All of it is defined as code and comes up with `make local-up`.

**Architecture:** Services use the OpenTelemetry SDK (`internal/platform/telemetry`) and push OTLP/HTTP to an **OTel Collector**. The Collector sends traces to **Tempo**, logs to **Loki**, and exposes metrics for **Prometheus** to scrape (kube-prometheus-stack, which also brings Grafana and Alertmanager). The W3C `traceparent` header travels in the NATS message headers, so one trace spans every hop of the saga. Dashboards and alert rules live in a small local chart, `charts/saga-observability`, which Argo CD can sync on day 4. Without `OTEL_EXPORTER_OTLP_ENDPOINT` the services export nothing, so Compose and the tests behave as before.

**Tech Stack:** OpenTelemetry Go SDK (OTLP/HTTP exporters, `otelhttp`, `otelslog`), `github.com/exaring/otelpgx`, OTel Collector (contrib distribution), kube-prometheus-stack, Tempo, Loki, metrics-server, `promtool`.

**Spec:** `docs/superpowers/specs/2026-11-12-k8s-portfolio-design.md` (§2 goals, §5 "traceparent travels in NATS headers", §6 "Observability", §7 day 3)

## Global Constraints

- Everything in the repo is in **English**.
- Every `kubectl`/`helm` call in scripts and the Makefile passes `--context kind-order-saga` / `--kube-context kind-order-saga`.
- New namespace `observability` holds every observability component. Nothing new is exposed: Grafana, Prometheus, Alertmanager and Tempo are reached only with `kubectl port-forward`. The Gateway and HTTPRoute stay unchanged.
- Collector address: `http://otel-collector.observability.svc.cluster.local:4318` (OTLP/HTTP). Set `fullnameOverride: otel-collector` so the Service has this name.
- Services read the standard `OTEL_*` variables. If `OTEL_EXPORTER_OTLP_ENDPOINT` is unset, nothing is exported and nothing tries to connect. Compose (`make up && make smoke`) and `go test -race ./...` keep working with no Collector.
- Telemetry failures never affect the saga. If the Collector is down, requests and handlers behave exactly as before, and only the exporters log their errors.
- No metric label has unbounded cardinality: no `order_id`, `event_id` or email address in metric labels. `order.id` goes on spans and logs only.
- Every saga span carries the attribute `order.id`. Every log line written inside a span carries `trace_id` and `span_id`.
- Health endpoints (`/healthz`, `/readyz`) produce no spans.
- Pin every third-party chart and image version in `deploy/local/versions.env`; no `latest` and no floating versions. Pick the latest stable at implementation time, check the chart's **current** repository (some Grafana charts have moved), and record versions and repositories in ADR 0008.
- No secrets in Git. The Grafana admin password is generated by `ensure_secrets` into the Secret `grafana-admin` (keys `admin-user`, `admin-password`) in `observability`, only if it does not already exist.
- Every container has requests and limits. The whole cluster, observability included, stays under **6 GB** of memory as reported by `kubectl top nodes`.
- Alerts go to Mailpit (`mailpit.platform.svc.cluster.local:1025`, no TLS) only when they carry the label `team: saga`. Every other alert goes to a `null` receiver.
- `make lint` reports 0 issues, `go test -race ./...` passes, `make chart-test` prints `CHART OK`, and `make local-up` stays idempotent.
- Day-4 items are out of scope: NetworkPolicies, Pod Security Admission labels and Argo CD.

## Review Focus

1. **The Collector is down or unreachable.** Orders keep completing, nothing blocks or crashes, and memory does not grow without bound. Tested in Task 1 (exporter pointed at a closed port) and drilled in Task 4 (Collector scaled to 0 under load).
2. **A message is redelivered, or its stored outcome is re-published.** Saga metrics count each order once: no double `completed`, no second duration sample. Tested in Task 3.
3. **A message arrives without `traceparent`**, for example one stored before day 3 or replayed from the DLQ. The consumer starts a new root span and handles the message normally. Tested in Task 2.
4. **Both `orders` replicas report the stuck-PENDING gauge.** The alert uses `max`, so it neither double-counts nor fires per pod. Tested in Task 5 with `promtool`.
5. **There is no traffic** (loadgen scaled to 0, or a fresh cluster). The SLO ratios have no data and no SLO alert fires. Tested in Task 5 with `promtool`.

### Task 1: Telemetry setup and log correlation

**Files:**
- Create: `internal/platform/telemetry/telemetry.go` and `telemetry_test.go`, plus `internal/platform/telemetry/telemetrytest/metrics.go`
- Modify: `internal/platform/logx/logx.go` and `logx_test.go`, `cmd/*/main.go` (all five)
- Modify: every saga log call in `internal/{orders,inventory,payments,notifications}` switches to the `*Context` variant (`InfoContext(ctx, …)` and so on) so the logs pick up the trace

**Interfaces:**
- Produces:
  - `telemetry.Setup(ctx context.Context, service string) (shutdown func(context.Context) error, err error)`.
    - Always installs the W3C `tracecontext` + `baggage` propagator and an SDK `TracerProvider` (so spans have valid IDs even when nothing is exported).
    - The resource has `service.name = service`. The SDK's own env handling lets `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` override it.
    - When `OTEL_EXPORTER_OTLP_ENDPOINT` is set, it adds the OTLP/HTTP trace exporter (batch span processor), an OTLP/HTTP metric exporter with a periodic reader (the interval follows `OTEL_METRIC_EXPORT_INTERVAL`), and an OTLP/HTTP log exporter with a batch processor. Each is installed as the global provider.
    - When the endpoint is unset, it installs no exporters and leaves the global meter and logger providers as no-ops.
    - `shutdown` flushes and stops everything it created.
  - `telemetrytest.NewReader() *sdkmetric.ManualReader`, which installs a global `MeterProvider` backed by the reader. Call it from `TestMain`.
  - `telemetrytest.Sum(t testing.TB, r *sdkmetric.ManualReader, name string, attrs ...attribute.KeyValue) int64`, which returns the current value of the counter series with exactly these attributes, or 0.
  - `telemetrytest.HistogramCount(t testing.TB, r *sdkmetric.ManualReader, name string) uint64`.
  - `logx.New(service, level string) *slog.Logger`, with the same signature as before. It fans out to the stdout JSON handler and an `otelslog` bridge handler (scope = service), both filtered at `level`, wrapped in a handler that adds `trace_id` and `span_id` (hex strings) when `ctx` carries a valid span context. With no global logger provider, the bridge is a no-op.
  - Each `cmd/<svc>/main.go`:
    1. Calls `telemetry.Setup` **before** `logx.New`. On error it writes to stderr and exits 1.
    2. Defers `shutdown` with a 5 s timeout context.

### Task 2: Traces across HTTP, NATS and Postgres

**Files:**
- Create: `internal/platform/events/tracing.go`, `internal/platform/events/tracing_test.go`
- Modify: `internal/platform/events/{publish.go,consume.go}`, `internal/orders/service.go` (wraps the API handler), `internal/loadgen/service.go`, `internal/platform/pgutil/pgutil.go`, `tests/e2e/saga_test.go`, `go.mod`

**Interfaces:**
- Consumes: `telemetry.Setup` and the global propagator from Task 1.
- Produces:
  - `headerCarrier` (type `nats.Header`) implements `propagation.TextMapCarrier`. The tracer is named `github.com/jmmorell/k8s-order-saga/internal/platform/events`.
  - **`Publish`** (signature unchanged):
    - Starts a span `publish <subject>`, kind `Producer`, with attributes `messaging.system=nats`, `messaging.destination.name=<subject>`, `messaging.message.id=<event id>` and `order.id`.
    - Injects the span context into the message headers.
    - Records the error and sets status Error on failure.
  - **`Consume`**:
    - Extracts the context from the message headers.
    - Starts a span `process <subject>`, kind `Consumer`, with the same attributes plus `messaging.consumer.group.name=<durable>` and `messaging.nats.delivery_attempt=<n>`.
    - Passes the span context to the handler and ends the span after the ack, nak or dead-letter.
    - On a handler error, records the error and sets status Error.
    - A message with no `traceparent` gets a new root span.
  - `deadLetter` copies `traceparent` (and `tracestate` if present) into the DLQ message headers.
  - **Orders API** (`Routes()` is unchanged, the root mux in `Run` changes):
    - Wraps the API handler (not the health mux) in `otelhttp.NewHandler`.
    - Names spans after the matched route pattern (`POST /orders`, `GET /orders/{id}`), using `r.Pattern` in a span-name formatter. Falls back to the method alone.
    - Sets `order.id` on the server span once the id is known.
  - loadgen's `http.Client` uses `otelhttp.NewTransport`, so a trace starts in loadgen.
  - `pgutil.Connect` sets `config.ConnConfig.Tracer = otelpgx.NewTracer()` (`github.com/exaring/otelpgx`).

|---|---|---|---|---|

| `saga.payments` | counter | `result` ∈ `succeeded`, `failed` | first charge only, not on re-publish | `saga_payments_total` |
| `saga.inventory.operations` | counter | `result` ∈ `reserved`, `rejected`, `released` | first time only, not on re-publish | `saga_inventory_operations_total` |

### Task 5: Dashboard, SLO and alerts as code

**Files:**
- Create: `charts/saga-observability/{Chart.yaml,values.yaml}`, `charts/saga-observability/templates/{prometheusrule.yaml,dashboards.yaml}`
- Create: `charts/saga-observability/rules/{saga.rules.yaml,saga.rules.test.yaml}`, `charts/saga-observability/dashboards/saga.json`
- Create: `scripts/obs-check.sh`
- Modify: `scripts/local-up.sh` (`install_observability` also installs this chart into `observability`), `Makefile` (targets `rules-test`, `obs-check`), `scripts/chart-test.sh` (lint and render this chart too)

**Interfaces:**
- Consumes: the live metric names that Task 4 recorded. If a name differs from the Task 3 table, the live name wins.
- Produces:
  - `rules/saga.rules.yaml` is a plain Prometheus rule file, so `promtool` tests the same bytes that ship. `templates/prometheusrule.yaml` embeds it with `.Files.Get` into a `PrometheusRule`. `templates/dashboards.yaml` creates one ConfigMap per file in `dashboards/`, labelled `grafana_dashboard: "1"`.
  - **SLO:** 99 % of orders reach a final state within 5 s.
    - Recording rules `saga:slo_good_ratio:rate5m`, `:rate30m`, `:rate1h` and `:rate6h`, each equal to `sum(rate(saga_order_duration_seconds_bucket{le="5"}[W])) / sum(rate(saga_order_duration_seconds_count[W]))`.
    - Also `saga:orders_completed:rate5m`, which is `sum by (status, reason)` of the completed rate.
  - **Alerts.** All carry `team: saga`, plus a `severity` and a `summary` annotation.

| Alert | Expression (shape) | for | severity |
|---|---|---|---|
| `SagaSLOFastBurn` | `(1 - ratio1h) > 14.4 * 0.01 and (1 - ratio5m) > 14.4 * 0.01` | 2m | critical |
| `SagaSLOSlowBurn` | `(1 - ratio6h) > 6 * 0.01 and (1 - ratio30m) > 6 * 0.01` | 15m | warning |
| `PaymentErrorRateHigh` | `sum(rate(saga_payments_total{result="failed"}[5m])) / sum(rate(saga_payments_total[5m])) > 0.25` | 5m | warning |
| `EventsDeadLettered` | `sum(increase(saga_events_consumed_total{result="dead_letter"}[10m])) > 0` | 0m | warning |
| `OrdersStuckPending` | `max(saga_orders_stuck_pending) > 0` | 2m | critical |

  - **Dashboard `saga.json`** (uid `saga`, title "Order saga"). Panels:
    1. Orders created/s.
    2. Completed/s by status and reason.
    3. Final-state latency p50/p95/p99.
    4. SLO good ratio (1 h) against the 99 % line, plus the fast-burn rate.
